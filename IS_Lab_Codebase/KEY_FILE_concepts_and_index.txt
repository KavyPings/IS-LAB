PART 2 - HOW TO ANSWER A SCENARIO QUESTION IN 6 STEPS
================================================================================

Almost every exam question is the same shape as the EduSecure sample:
a story, a list of roles, and three or four cryptographic primitives.

STEP 1 - UNDERLINE THE PRIMITIVES IN THE QUESTION
    "uses DES ... RSA digital signatures ... SHA-256 hashing"
    -> you now know which three functions you need.

STEP 2 - WRITE THE ROLES DICT FIRST
    ROLES = {"student": {"upload", "view_own"},
             "faculty": {"decrypt", "verify", "view_all"},
             "hod":     {"view_hashes", "verify"}}
    Copy the allowed actions straight from the question's bullet points.
    This single dict is worth the whole "access control" mark.

STEP 3 - COPY edusecure.py AND SWAP THE PRIMITIVES
    Section 2 -> the encryption algorithm
    Section 3 -> the hash
    Section 4 -> the signature scheme
    Everything else (storage, login, menus, timestamps) already works.

STEP 4 - GET THE ORDER RIGHT
    upload : encrypt -> hash the CIPHERTEXT -> sign the hash
    review : recompute the hash -> verify the signature -> then decrypt
    If the question words it differently, follow the question.

STEP 5 - STORE WITH TIMESTAMPS
    Every question says "with timestamps". Use
        datetime.now().strftime("%Y-%m-%d %H:%M:%S")
    and put it in every stored record. Bytes go into JSON as base64.

STEP 6 - ADD A demo() FUNCTION
    A non-interactive run that shows: a successful flow, a blocked role, and
    a tamper test. It takes two minutes to write and it demonstrates every
    mark on the rubric without you typing menu choices during the viva.

PART 5 - THINGS THAT COST MARKS
================================================================================
  * wrong key length for DES/AES        -> use make_key(key, size)
  * forgetting pad/unpad in ECB and CBC -> ValueError on decrypt
  * reusing a cipher object             -> create a new one each time
  * hashing a str instead of bytes      -> .encode() first
  * comparing digests with ==           -> use hmac.compare_digest
  * RSA-encrypting a long message       -> use hybrid encryption
  * "encrypting with ECC" directly      -> ECC needs ECIES/ECDH
  * reusing k in ElGamal/Schnorr/DSA    -> leaks the private key
  * using the raw DH number as a key    -> hash it first
  * no timestamps in stored records     -> the question always asks for them
  * storing private keys in plain text  -> "secure storage" means encrypted
  * signing with the public key         -> the PRIVATE key signs
  * verify() raising instead of returning False -> wrap it in try/except
  * a bare recv(1024) socket loop       -> use the 4-byte length framing
  * expecting Paillier to multiply      -> it ADDS; use ElGamal/raw RSA
  * expecting ElGamal to add            -> it MULTIPLIES; use Paillier
  * forgetting gcd(r, n) = 1 in Paillier encryption
  * L(x) written with / instead of //   -> needs integer division
  * pow(x, y) with no modulus           -> looks like a hang
  * using a RANDOMISED ciphertext as a search index KEY (the manual's bug)
    -> the index key must be deterministic: HMAC or a plain hash
  * forgetting .lower() on the indexed word or the query -> no matches
  * adding candidate IDs and calling it a tally -> use packed counters
  * claiming a searchable scheme leaks nothing -> it leaks counts and
    patterns; say so, it is a mark
  * printing a 1024-bit ciphertext in full -> print hex(c)[:30] + "..."
  * not making the program menu driven  -> the end-sem paper halves the marks
